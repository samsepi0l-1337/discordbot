# `/ticket` 상세 가이드 (Private Thread 기반)

이 프로젝트의 티켓 시스템은 채널 난립을 방지하기 위해 **비공개 스레드(Private Thread)** 방식을 사용하며, `ticket_sessions` 테이블을 통해 모든 티켓의 상태를 관리합니다.

---

## 1. 티켓 생성 로직 (`createTicketChannelTicket`)

1. **버튼 클릭**: 유저가 `/ticket panel`로 생성된 버튼을 클릭합니다.
2. **중복 체크**: 해당 유저가 이미 해당 서버에서 `open` 상태인 티켓을 가지고 있는지 확인합니다. (중복 생성 방지)
3. **스레드 생성**: 패널이 있는 채널 안에 **비공개 스레드**를 생성합니다.
4. **참여자 초대**:
    - 티켓을 연 유저(Opener)를 초대합니다.
    - `/ticket add-support-role/user`로 설정된 모든 스태프를 초대합니다.
5. **DB 기록**: `ticket_sessions` 테이블에 `opener_id`, `channel_id`(스레드 ID), `status='open'` 정보를 저장합니다.

---

## 2. 티켓 관리 로직 (`TicketService`)

### 클레임 (`claim` / `unclaim` / `transfer`)

- **로직**: `ticket_sessions`의 `claimed_by_id` 필드를 업데이트합니다.
- **UI 변화**: 티켓 상단 메시지의 버튼 구성이 변경되며(클레임 시 '언클레임' 버튼 등장), 현재 담당자가 누구인지 메시지에 표시됩니다.

### 참여자 관리 (`add` / `remove`)

- **로직**: Discord API의 스레드 멤버 관리 기능을 사용하여 특정 유저를 티켓에 초대하거나 내보냅니다. (명령어를 실행하는 채널이 티켓 스레드여야 함)

---

## 3. 티켓 종료 및 기록 로직 (`closeTicketSession`)

티켓 채널 내의 '닫기' 버튼을 누르거나 `/ticket close`를 실행할 때 작동합니다.

1. **상태 변경**: DB의 티켓 상태를 `closed`로 변경하고, 종료 시간과 종료한 사람을 기록합니다.
2. **트랜스크립트 생성 (`buildTranscriptText`)**:
    - 티켓 채널의 마지막 메시지 100개를 가져옵니다.
    - `[시간] 유저명: 내용` 형식으로 텍스트 파일을 생성합니다.
    - 첨부 파일이 있다면 URL을 함께 기록합니다.
3. **로그 전송**: `/ticket set-transcripts`로 설정된 채널이 있다면, 위에서 만든 텍스트 파일을 해당 채널로 업로드합니다.
4. **스레드 잠금**: 스레드를 **잠금(Lock)** 및 **보관(Archive)** 처리하여 더 이상 메시지를 작성할 수 없게 만듭니다.

---

## 4. 자동 관리 정책 (Cleanup)

- **메시지 기록 유지**: 기본적으로 30일간의 기록을 유지합니다. (환경 변수 `TICKET_RETENTION_DAYS`로 조절 가능)
- **자동 삭제**: `index.ts`는 매일 한 번씩 `closed` 상태이면서 `updated_at`이 설정 기간보다 오래된 티켓 데이터를 데이터베이스에서 삭제합니다.

---

## 5. 설정 커맨드 매개변수 상세

- **`/ticket show`**: 현재 서버의 티켓 설정(지원팀 역할/유저, 트랜스크립트 채널 등)을 요약해서 보여줍니다.
- **`/ticket set-category`**: (레거시 지원용) 향후 텍스트 채널 방식 전환 시 사용할 카테고리를 지정합니다.
- **`/ticket add-support-role`**: 티켓이 열릴 때마다 자동으로 초대받을 역할을 추가합니다.
- **`/ticket add-support-user`**: 특정 유저를 스태프로 지정하여 모든 티켓에 참여시킵니다.
- **`/ticket panel`**: 현재 명령어를 입력한 채널에 티켓 생성 버튼이 담긴 메시지를 전송합니다.
